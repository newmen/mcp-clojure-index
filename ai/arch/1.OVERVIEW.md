## Modules and their responsibilities

| Module | Namespace | Responsibility | Depends on |
|--------|-----------|-----------------|------------|
| Config | `mcp.config` | Reading `config.edn`, resolving fields from the environment (`VSCODE_CWD`, `QD_PROJECT_ROOT`, `QD_COLLECTION`), validation | — |
| Parser | `mcp.parser` | Parsing .clj/.cljc/.cljs/.edn files into CST (rewrite-clj), semantic chunking, metadata extraction (def, defn, defn-, defprotocol, defrecord, defmacro, ns), handling syntax errors without interrupting indexing | config |
| Symbol index | `mcp.symbol-index` | Storing and searching symbols (functions, macros, protocols, records, vars) | parser |
| Dependency graph | `mcp.graph` | Building the call graph (callers/callees), protocol inheritance graph, ns → ns relationships | symbol-index, parser |
| Embeddings | `mcp.embeddings` | Generating embeddings via Ollama (embedding of code and queries) | config |
| Qdrant | `mcp.qdrant` | Vector store operations: upsert, search, collection management | config |
| Watcher | `mcp.watcher` | Tracking file changes (Java WatchService), dispatching incremental reindexing | parser, qdrant, embeddings, config |
| Hybrid search | `mcp.search` | Semantic search via Qdrant + reranking (Cross Encoder) + optional expansion via the symbol index and graph | qdrant, embeddings, graph |
| MCP tools | `mcp.tools` | Registration and dispatch of MCP tools | search, symbol-index, graph |
| MCP server | `mcp.server` | Entry point, server lifecycle, MCP transport (stdio/HTTP) | tools, config |
## Principles

1. **Unidirectional dependencies** — dependencies flow from top to bottom. Lower modules do not import higher ones.
2. **Single responsibility** — each module solves exactly one task.
3. **Protocol-based extension** — for replacing components (embeddings, Qdrant → another vector store, SymbolIndex, Graph) Clojure protocols or multimethods are used.
4. **Data via EDN** — all inter-module data is passed as plain Clojure structures (map, vector), without shared mutable objects.
5. **State recovery on restart** — at server start the in-memory structures (SymbolIndex, Graph) are restored from Qdrant (scroll payload) instead of a full rebuild. Only changed files go through a full reindex. Qdrant is the single source of truth for the saved state.

## Cyclic dependency check

Dependency graph (import direction):

```
mcp.config        → (no dependencies)
mcp.parser        → mcp.config
mcp.symbol-index  → mcp.parser
mcp.graph         → mcp.symbol-index, mcp.parser
mcp.embeddings    → mcp.config
mcp.qdrant        → (no dependencies from other modules; config is passed as a parameter)
mcp.watcher       → mcp.parser, mcp.qdrant, mcp.embeddings, mcp.config
mcp.search        → mcp.qdrant, mcp.embeddings, mcp.graph
mcp.tools         → mcp.search, mcp.symbol-index, mcp.graph
mcp.server        → mcp.tools, mcp.config
```

Cyclic dependencies: **none**. The graph is a DAG.
