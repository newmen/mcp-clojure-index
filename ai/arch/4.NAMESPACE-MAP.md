# Namespace map and directory structure

## src/ structure

```
src/mcp/
├── server.clj         ;; mcp.server
├── tools.clj          ;; mcp.tools
├── parser.clj         ;; mcp.parser
├── symbol_index.clj   ;; mcp.symbol-index
├── graph.clj          ;; mcp.graph
├── embeddings.clj     ;; mcp.embeddings
├── qdrant.clj         ;; mcp.qdrant
├── watcher.clj        ;; mcp.watcher (Java WatchService)
├── search.clj         ;; mcp.search (hybrid search)
└── config.clj         ;; mcp.config (reading config.edn)
```

## Namespace dependency graph (no cycles)

```
mcp.config      → (no dependencies)
mcp.parser      → mcp.config
mcp.embeddings  → mcp.config
mcp.symbol-index → mcp.parser
mcp.graph       → mcp.symbol-index, mcp.parser
mcp.qdrant      → (no dependencies from other modules)
mcp.watcher     → mcp.parser, mcp.qdrant, mcp.embeddings, mcp.config
mcp.search      → mcp.qdrant, mcp.embeddings, mcp.graph
mcp.tools       → mcp.search, mcp.symbol-index, mcp.graph
mcp.server      → mcp.tools, mcp.config
```

Visualization of directed dependencies (topological order):

```
Layer 0 (core, no deps):
  mcp.config
  mcp.qdrant

Layer 1 (depends on layer 0):
  mcp.parser      (→ config)
  mcp.embeddings  (→ config)

Layer 2 (depends on layers 0–1):
  mcp.symbol-index (→ parser)

Layer 3 (depends on layers 0–2):
  mcp.graph       (→ symbol-index, parser)

Layer 4 (depends on layers 0–3):
  mcp.watcher     (→ parser, qdrant, embeddings, config)
  mcp.search      (→ qdrant, embeddings, graph)

Layer 5 (depends on layers 0–4):
  mcp.tools       (→ search, symbol-index, graph)

Layer 6 (top, depends on layers 0–5):
  mcp.server      (→ tools, config)
```

Conclusion: layered, strictly unidirectional. No cycles.
