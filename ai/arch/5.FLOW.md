# Flow diagrams

## Indexing flow

```
File System (.clj files)
    │
    ▼
mcp.parser/parse-project (walk .clj/.cljc/.cljs/.edn)
    │
    ├── rewrite-clj → CST
    ├── semantic chunking (by s-expressions: defn, defn-, defprotocol, defrecord, defmacro, ns)
    ├── metadata extraction (doc, arglists, tag, visibility)
    ├── symbol extraction (names, referenced symbols)
    └── error collection (ParseError → doesn't interrupt indexing of other files)
    │
    ├──→ mcp.symbol-index/build-index
    │     └── SymbolRecord for each symbol
    │
    ├──→ mcp.graph/build-graph
    │     ├── analysis of function calls inside bodies
    │     ├── analysis of require/use in ns
    │     └── building callers/callees
    │
    └──→ mcp.embeddings/generate (batch of N chunks)
            │
            ├── hash check → embedding cache (if the hash matches — skip)
            └──→ mcp.qdrant/upsert! (with CodeChunk payload)
```

## Search flow (MCP Tool Call)

```
LLM Agent
    │
    ▼
mcp.tools (semantic_search)
    │
    ├── mcp.embeddings/generate [query]
    │     └── Ollama / nomic-embed-code → query embedding
    │
    ├── mcp.qdrant/search [embedding, top-k=100]
    │     └── Qdrant → top-100 chunks
    │
    ├── mcp.embeddings/rerank [query, top-100]
    │     └── Ollama / bce-reranker → top-10 chunks
    │
    ├── (optional) mcp.symbol-index / mcp.graph
    │     └── context expansion: callers, callees, protocols
    │
    └── Context Assembly → return to LLM
```

## State recovery flow on restart

```
Server start
    │
    ├── mcp.qdrant/collection-info → :points-count or nil
    │     └── 0 → reindex-all!
    │
    ├── mcp.qdrant/scroll-all (payload only, without vectors)
    │     └── seq of CodeChunk (from the payload of each point)
    │
    ├── mcp.symbol-index/build-index (from recovered CodeChunks)
    │     └── SymbolIndex (in-memory)
    │
    ├── mcp.graph/build-graph (from recovered CodeChunks + SymbolIndex)
    │     └── Graph (in-memory)
    │
    ├── Collect file → file_hash (SHA-256 of the whole file) from recovered CodeChunks
    │
    ├── Walk the project FS (with exclude rules), compute file_hash for each file
    │     ├── file_hash matches → skip
    │     ├── file_hash doesn't match → process-modify (parse → delete old → generate → upsert)
    │     ├── file is in the hash-map, not on the FS → process-delete
    │     └── file is not on the hash-map → process-modify (as new)
    │
    └── mcp.watcher/start-watching! (incremental monitoring)
```

## Incremental indexing flow

```
FileWatcher detects change
    │
    ├── modified file.clj → mcp.parser/parse-file
    │     ├── mcp.symbol-index/remove-file! (remove old symbols of the file)
    │     ├── mcp.symbol-index/add-file! (add new symbols of the file)
    │     ├── mcp.graph/remove-file! (remove old edges of the file)
    │     ├── mcp.graph/add-file! (add new edges of the file)
    │     ├── mcp.qdrant/delete! (old chunks by file)
    │     ├── mcp.embeddings/generate (new chunks)
    │     └── mcp.qdrant/upsert! (new chunks)
    │
    ├── deleted file.clj → mcp.qdrant/delete!
    │     ├── mcp.symbol-index/remove-file!
    │     └── mcp.graph/remove-file!
    │
    ├── new file.clj → as modified
    └── renamed file.clj (ENTRY_DELETE + ENTRY_CREATE within a ~100ms debounce window)
            ├── merge as a move: old-path → new-path
            ├── if the content unchanged (hash matches):
            │     ├── mcp.qdrant/update-file-path! (update the file field in the payload)
            │     ├── mcp.symbol-index/update-file-path! (update file in SymbolRecord)
            │     └── mcp.graph/update-file-path! (update file in Edge)
            └── if the content changed — as modified (delete old + generate + upsert new)
```

## Configuring MCP for Kilo Code

To connect the server to Kilo Code (or any MCP client), the MCP server is registered **once** in the global Kilo Code config (`~/.config/kilo/kilo.jsonc` or equivalent):

```json
{
  "mcp": {
    "clojure-code-index": {
      "type": "local",
      "command": ["lein", "run"],
      "args": ["resources/config.edn"],
      "workingDirectory": "/path/to/mcp-server",
      "enabled": true
    }
  }
}
```

**Per-project configuration is not required.** The server automatically determines the root of the indexed project through the environment:

1. **`VSCODE_CWD`** — set by VSCode and points to the root of the opened workspace.
2. **`user.dir`** — a Java system property pointing to the working directory (for launching outside VSCode).

The Qdrant collection name is computed from the last segment of the root-path (for example, `/Users/altermn/projects/clojure/mcp` → `mcp-collection`).

The embedding cache is placed inside the indexed project: `<root-path>/.mcp/embedding-cache`.

### Per-project override

If it is necessary to override the collection for a specific project, it is enough to set the environment variable `QD_COLLECTION` before launching VSCode/Kilo Code, or specify `:qdrant/collection` in `config.edn`:

```bash
# Bash: per-project override
export QD_COLLECTION="my-project-custom"
code /path/to/project
```

Or, when running outside VSCode, specify `QD_PROJECT_ROOT`:

```bash
QD_PROJECT_ROOT=/path/to/project lein run resources/config.edn
```
