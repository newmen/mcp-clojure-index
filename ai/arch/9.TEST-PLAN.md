# Test plan

## Tools

- `clojure.test` — unit tests
- Kaocha (`lambdaisland/kaocha`) — test runner with filtering and reporting
- `criterium` — performance benchmarking
- `InMemoryStore` — in-memory implementation of VectorStore for tests without Qdrant

## Testing levels

### Unit tests (in isolation, without external dependencies)

| Module | What to test | Mocks/fixtures |
|--------|--------------|---------------|
| `mcp.parser` | parse-file on .clj/.cljc/.cljs/.edn; handling of syntax errors; extraction of metadata and visibility | Test files in `test/mcp/fixtures/` |
| `mcp.symbol-index` | build-index, find-symbol, find-namespace, find-by-type, find-by-protocol, find-by-record | Result of parse-file |
| `mcp.graph` | build-graph, find-callers, find-callees; correctness of Edge with chunk-id | SymbolIndex from parser |
| `mcp.embeddings` | generate, rerank format of input/output data | `InMemoryEmbeddingProvider` |
| `mcp.qdrant` | create-collection!, upsert!, delete!, search | `InMemoryStore` (implements VectorStore) |
| `mcp.tools` | registration of tools, JSON Schema of parameters | Mocks of all services |
| `mcp.watcher` | calling callbacks on of FS events | Mock WatchService |

### Integration tests (with real dependencies)

| Test | What it checks |
|------|---------------|
| Parser → Embeddings → SymbolIndex → Graph | Full pipeline of indexing a single file |
| Parser → Embeddings → Qdrant | End-to-end chunk saving flow |
| Watcher → Parser → Qdrant | Incremental reindexing |
| Tools → Qdrant → Embeddings | Hybrid search + reranking |
| Qdrant scroll → SymbolIndex → Graph | State recovery on of restart: scroll points from Qdrant → build SymbolIndex and Graph → compare with the reference from parse-project |
| Qdrant scroll → hash sync | Recovery + FS sync: change one file → restart → check that only it changed |

### Performance tests (criterium)

| Test | Metric |
|------|-------|
| parse-file on a large file (1000+ lines) | Time, memory |
| `generate` batch (100 chunks) | Time |
| search + rerank (top-100 → top-10) | Time, p95 latency |
| incremental reindexing of one file | Time |
| full project indexing (mcp as the target) | Time, memory usage |

## Acceptance criteria

- [ ] All unit tests pass (`kaocha` — 0 failures)
- [ ] The parser correctly handles files with syntax errors (returns ParseError, does not crash)
- [ ] Incremental indexing: changing one file does not rebuild the whole collection
- [ ] The dimensionality of all embeddings is the same
- [ ] Search + rerank returns top-10 results
- [ ] Qdrant batch upsert works for 100+ chunks
- [ ] No memory leaks during long watcher runtime (24h)
- [ ] The search results are stable point (same query → same results)
- [ ] In the Qdrant, symbol index, and graph of dependency on the deleted file — all its entries are absent
- [ ] On file rename, the index is actual by the new path, no duplicate entries by the old path
- [ ] Recovery: scroll from Qdrant → SymbolIndex + Graph are equivalent to those built from scratch via parse-project
- [ ] Recovery: on restart with an existing non-empty collection `reindex-all!` is not performed
- [ ] Recovery: scroll does not request embedding vectors (with_vector=false)
- [ ] Recovery: a changed file is reindexed, the others are skipped
- [ ] Recovery: a deleted file is removed from the index
- [ ] Recovery: at `:qdrant/recreate? = true` a full `reindex-all!` is executed
