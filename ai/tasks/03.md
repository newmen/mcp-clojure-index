# Task 3. Semantic splitting of code

## Objective

On the basis of the CST it is necessary to identify independent semantic units of indexing. The basic indexing unit is the top-level language definition (`defn`, `defmacro`, `defprotocol`, `defrecord`, `deftype`, `def`, `ns`). Each chunk must contain the full source text of the corresponding definition, without truncation or formatting changes. Simultaneously, it is necessary to determine the line range (`start_line`, `end_line`), the definition type (`type`), and the location in the source file (`file`). For each chunk a stable content hash (`hash`) must be computed, which will be used in incremental indexing to detect changed elements. It is the output of this task that becomes the basis for forming the payload stored in Qdrant.

Example of the result of processing one definition:

```json
{
  "text": "(defn create-user ...)",
  "type": "function",
  "file": "src/bank/user.clj",
  "start_line": 81,
  "end_line": 120,
  "hash": "6d0b9d7..."
}
```

### Tools

- rewrite-clj
- rewrite-clj zipper API
- Java MessageDigest (SHA-256)

### Input

Concrete Syntax Tree.

### Output

A collection of semantic chunks with the definition text, line range, and a content checksum.

### Acceptance criteria

- each chunk represents a complete language construct;
- there are no chunk intersections;
- each chunk contains the full source text;
- line ranges are defined;
- a stable content hash is computed for each chunk.
