# Task 4. Building the symbol index

## Description

For each semantic chunk it is necessary to extract structural information describing the language definition. The namespace, the symbol name, the definition type, the visibility scope (`public`/`private`), the argument list, the docstring, metadata, and the location in the source file must be determined. The obtained data is used both for building the symbol index and for forming the metadata stored together with the embedding in Qdrant. The information must be normalized and have a single format regardless of the definition type. This stage is responsible for forming almost all payload fields, except for the definition text and the embedding.

Example of formed metadata:

```json
{
  "language": "clojure",
  "namespace": "bank.user",
  "symbol": "create-user",
  "type": "function",
  "visibility": "public",
  "file": "src/bank/user.clj",
  "start_line": 81,
  "end_line": 120,
  "hash": "6d0b9d7..."
}
```

### Tools

- rewrite-clj
- Clojure Spec (if necessary)

### Input

A collection of semantic chunks.

### Output

A symbol index and structured metadata for each chunk.

### Acceptance criteria

- the namespaces of all symbols are defined;
- the names of all symbols are defined;
- the definition types are defined;
- the visibility scope is correctly determined;
- the metadata contains all fields needed to form the Qdrant payload.
