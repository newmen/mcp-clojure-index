# Task 6. Embedding generation

## Description

For each semantic chunk, it is necessary to form the text that will be used to build the embedding. As the input to the model, it is recommended to use not only the source code, but also additional semantic information: the namespace, the symbol name, and the docstring, if present. The resulting text is passed to the local embedding model through Ollama. The result is a vector of fixed dimensionality, which is subsequently combined with the metadata formed in the previous stages. If the chunk content has not changed (determined by the `hash` field), re-generating the embedding is not performed.

Example of the text passed to the model:

```text
Language:
Clojure

Namespace:
bank.user

Symbol:
create-user

Docstring:
Creates a customer user and assigns relationship manager to customer.

Code:

(defn create-user ...)
```

### Tools

- Ollama
- Embedding Generation (by default: vishalraj/nomic-embed-code)

### Input

The semantic chunk and the metadata.

### Output

The embedding of a fixed dimensionality for the given definition.

### Acceptance criteria

- all chunks receive embeddings;
- no regeneration when the `hash` is unchanged;
- model errors are handled correctly;
- the dimensionality of all embeddings is the same.
