# Task 7. Index storage

## Description

It is necessary to implement the semantic index storage layer in Qdrant. For each definition, the embedding and the payload containing all the structural information needed for later search and navigation are stored. The payload must be fully formed before writing and must contain both the definition text and the metadata extracted in the previous steps. Loading must support batch writing (`upsert`) of a large number of objects and deletion of all records belonging to a single file during incremental reindexing. The payload structure must be stable and independent of the definition type.

Example payload:

```json
{
  "id": "...",
  "text": "(defn create-user ...)",
  "language": "clojure",
  "namespace": "bank.user",
  "symbol": "create-user",
  "type": "function",
  "visibility": "public",
  "file": "src/bank/user.clj",
  "start_line": 81,
  "end_line": 120,
  "hash": "6d0b9d7..."
}
```

The Qdrant address is set in the config; by default: http://localhost:6333/

### Tools

- Qdrant
- Qdrant HTTP API

### Input

The embedding and the fully formed payload.

### Output

A collection of objects in Qdrant.

### Acceptance criteria

- each chunk is stored as a single record;
- the payload contains all mandatory fields;
- batch loading is supported;
- deletion of all records of a file is supported;
- the payload structure is the same for all definitions.
