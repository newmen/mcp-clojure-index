# Task 11. Restoring the index state on server restart

## Description

On MCP server restart, the in-memory symbol index and dependency graphs are lost. The current `reindex-all!` implementation rebuilds the whole project, which includes:

- scanning the file system (FS I/O);
- parsing all .clj/.cljc/.cljs/.edn files;
- extracting symbols and building SymbolIndex;
- building the dependency graphs;
- generating embeddings over HTTP (Ollama) — the bottleneck;
- upserting into Qdrant.

If the collection in Qdrant already exists and contains fresh data, a full rebuild is redundant.

It is necessary to implement a mechanism for restoring the state of the in-memory structures (SymbolIndex, Graph) from Qdrant at server start, so that:

- no re-generation of embeddings for already indexed files;
- no re-upsert of points in Qdrant;
- re-index only those files that changed since the last indexing.

### Mechanism

#### 1. Scroll points from Qdrant

At server start, if the collection in Qdrant exists and is not empty:

1. Perform a scroll (batch read) of all points from the collection with the payload (without vectors to save memory and bandwidth).
2. Restore the CodeChunk for each point from the payload (11 fields: id, text, language, namespace, symbol, type, visibility, file, start_line, end_line, hash).
3. Build the SymbolIndex from the restored CodeChunks (through `build-index`).
4. Build the Graph from the restored CodeChunks and the SymbolIndex (through `build-graph`).

#### 2. Finding changed files

After restoring the in-memory structures:

1. Collect `file → set(hash)` from the restored CodeChunks.
2. Walk the project file system (search .clj/.cljc/.cljs/.edn taking the exclude rules into account).
3. For each file compute the SHA-256 hash of the current content.
4. Compare with the hash from Qdrant:
   - **Hash is the same** — the file has not changed, skip.
   - **Hash differs, or there is no file in Qdrant** — perform a full reindex of the file (as in `process-modify`): parsing → deleting old points → generating embeddings → upsert → updating SymbolIndex and Graph.
   - **The file is in Qdrant, but is missing on the FS** — delete from Qdrant, SymbolIndex, and Graph (as in `process-delete`).

#### 3. Starting the watcher

After the restore and sync, start the Java WatchService for incremental change tracking.

#### 4. Conditions for skipping the restore

If at least one of the following holds, the server performs a full `reindex-all!`:

- The collection in Qdrant does not exist.
- The collection is empty.
- The `:qdrant/recreate?` config parameter equals `true`.
- The number of points in Qdrant does not match the number of .clj/.cljc/.cljs/.edn files in the project (a rough integrity check) — optional.

### New functions in Qdrant

Add `mcp.qdrant`:

```clojure
(collection-info config)
  ;; Input:  Config
  ;; Output: {:points-count int} or nil (collection does not exist)
  ;; Side effects: HTTP request to Qdrant

(scroll-all config)
  ;; Input:  Config
  ;; Output: seq of CodeChunk (restored from the payload of each point)
  ;; Side effects: HTTP request to Qdrant (scroll with pagination by 100 points)
```

### Tools

- Qdrant REST API (scroll /collections/{name}/points/scroll)
- Java File System API (FS traversal, SHA-256)
- Existing `mcp.symbol-index/build-index` and `mcp.graph/build-graph`

### Input

The MCP server configuration (config.edn), the existing Qdrant collection, the file system.

### Output

Restored SymbolIndex and Graph stored in atoms, a ready-to-use watcher.

### Acceptance criteria

- at startup with an existing non-empty Qdrant collection, the server does not perform a full `reindex-all!`;
- the restored SymbolIndex and Graph are equivalent to those built from scratch (test: scroll → build-index = parse-project → build-index);
- files changed since the last index are re-indexed, the rest are skipped;
- files deleted since the last index are removed from the index;
- the point scroll does not request embedding vectors (with_vector=false), minimizing the transferred data;
- if the collection is missing or the `:qdrant/recreate?` flag is set, a full reindex is performed as a fallback;
- all unit tests pass.
