# Task 14. Automatic determination of root-path and collection

## Description

Implement automatic determination of `:index/root-path` and `:qdrant/collection` from the environment, so that the MCP server can index any Clojure project without changing `config.edn`.

## Details

### 1. The `mcp.config/resolve-config` function

Add to `mcp.config` a function that enriches the config fields after `load-config`:

```clojure
(defn resolve-config
  "Resolve computed config fields. Priority chain:
   1. Explicit value from config.edn
   2. Environment variable
   3. Computed from other fields
   4. Hardcoded default"
  [cfg]
  ...)
```

**Resolution rules:**

For `:index/root-path`:
1. Explicit in `config.edn` (`(:index/root-path cfg)`)
2. `(System/getenv "QD_PROJECT_ROOT")`
3. `(System/getenv "VSCODE_CWD")`
4. `(System/getProperty "user.dir")`
5. `"."` (fallback)

For `:qdrant/collection`:
1. Explicit in `config.edn`
2. `(System/getenv "QD_COLLECTION")`
3. `(str (last (s/split normalized-root-path #"/")) "-collection")`
4. `"clojure-code-index"` (fallback)

### 2. Integration into `mcp.server/-main`

Change `-main` to call `resolve-config` between `load-config` and `validate-config`:

```clojure
(defn -main
  [& args]
  (let [config-path (or (first args) "resources/config.edn")
        cfg (-> (config/load-config config-path)
                (config/resolve-config)
                (config/validate-config))]
    (start cfg)))
```

### 3. Path normalization

`root-path` must be normalized:
- The trailing `/` is removed (if any)
- Absolute paths remain as is
- Relative paths are resolved relative to `user.dir`

### 4. Tests

Add tests to `test/mcp/config_test.clj`:

- `resolve-config-uses-explicit-root-path` — the explicit value from config.edn is not overridden
- `resolve-config-uses-vscode-cwd` — when there is no explicit root-path, `VSCODE_CWD` is used
- `resolve-config-falls-back-to-user-dir` — when there are no env vars, `user.dir` is used
- `resolve-config-computes-collection-from-root` — the collection is computed from the last segment of the path
- `resolve-config-uses-explicit-collection` — the explicit collection is not overridden
- `resolve-config-uses-qd-collection-env` — the `QD_COLLECTION` env overrides the computed collection
- `resolve-config-normalizes-trailing-slash` — `/path/to/project/` → `/path/to/project`
- `resolve-config-empty-env-not-used` — an empty env variable does not override the explicit value

**Important:** the env-var tests use `with-redefs` for `System/getenv` to not depend on the real environment.
