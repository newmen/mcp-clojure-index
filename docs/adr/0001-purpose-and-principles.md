# Purpose: fewer agent tokens than grep, with better precision

The server exists to cut the tokens an LLM agent spends understanding Clojure code. Every tool must beat the agent's default (`grep` plus reading files) on two axes at once: the answer is **smaller** and it is **more complete or more precise** (aliases, `:refer`, `#'var`, `with-redefs`, values passed to higher-order functions). A tool that loses on either axis gets abandoned: an agent that receives one oversized or wrong answer stops trusting the whole server and returns to `grep` for the rest of the session. Precise navigation and semantic search are equally important; the decisions in ADR-0002 to ADR-0006 follow from this one.

"Smaller" is measured against the grep and reads that give the agent the same information, not against the cheapest grep that touches the question. For "what is in this namespace" `rg '^\s*\(def'` is cheaper, but it misses specs written as `(s/def` with an alias, protocol methods and multi-line arglists, and says nothing about who requires the namespace; what answers the question is reading the file. A tool may therefore be bigger than a bare grep by exactly the information that grep cannot give, and no more: its default answer carries only what the next step needs (ADR-0006); in `namespace_summary`, for example, the Definitions' Type signatures and Docstring summaries are opt-in (`detail: true`). ADR-0009 measures both baselines and reports the answers that exceed the careful one.
